# 手機導覽設計簡報

小綠是海生館裡陪訪客走路的綠蠵龜。手機畫面要讓人在嘈雜、反光、一手拿著的狀況下，一眼知道現在能做什麼。

## 誰在用

- **一般訪客**：走馬看花，想聽一眼就能懂的介紹，不想學操作。
- **帶小孩的家長**：一手牽孩子、一手拿手機，句子要短，按鈕要大，答錯也不能像考試。
- **年長訪客**：需要大字、高對比、不要擠在一起的小字和半透明底。
- **學生**：願意做一題小挑戰、追問一句，但仍沒耐心看研究用語。

評審與工作人員不是預設讀者。技術數字留在 `?debug=1`。

## 現場

人在走，常常單手、視線很短。展廳可能反光、很吵。語音只是輔助，文字要自己站住。一次只處理一件事：聽、問、答一題，或把小綠送到展示箱。

## 原則

1. **一屏一件主動作。** 主按鈕用實心，其餘動作一樣大，但視覺上退後。不要把前測、後測、連線數、計時器跟主動作排在一起。
2. **漸進揭露。** 評審改分組、換手機的票券、省電、拍照辨識、前測後測，收在摺疊區。展開才出現。
3. **訪客不看研究用語。** 貝氏知識追蹤的百分比、策略名稱與理由、耗時估計、連線的手機／展示箱數量、剩餘參觀時間，預設不顯示。網址加上 `?debug=1` 後寫入這個分頁的 sessionStorage，換頁仍看得到；`?debug=0` 關掉。教學用的說明句子仍給訪客，只是不附策略術語。
4. **WCAG AA。** 內文與按鈕文字對比至少 4.5:1，大標題至少 3:1。可點區域至少 44px，主按鈕 56px。重點文字不小於 16px。焦點用明顯的外框。尊重 `prefers-reduced-motion`。

## 視覺

淺海為底、白卡片、深青文字與主按鈕、暖沙色作次要按鈕。圓角卡片、固定間距、襯線標題加黑體內文。小綠待在深色圓窗裡，讓角色從背景裡浮出來。動效只做短的浮入與按壓，不搶內容。

## 流程

首頁是小綠和四個大按鈕：聽小綠介紹、問小綠、小挑戰、送到展示箱。展區用三個大選項切換。小挑戰一次一題，答完立刻說對或不對。對話是氣泡加上建議問題。展示箱頁負責送出、收回、團體挑戰，以及把問題送上大螢幕。
